# Lady Victoria — сайт салону краси

Сайт-візитівка салону краси Lady Victoria: каталог послуг з цінами, галерея робіт,
майстри, відгуки, FAQ і контакти. Побудований на [Astro](https://astro.build) —
статичний сайт без бекенду й бази даних, автоматично публікується на GitHub Pages
при кожному push у `main`.

Запис на процедуру — через кнопку **«Записатися»** (веде в Instagram Direct, коли
посилання буде додано) і плашку телефону (`tel:`-посилання, дзвінок в один клік).

## Швидкий старт

```bash
npm install       # встановити залежності
npm run dev        # локальний сервер розробки на http://localhost:4321
npm run build       # перевірка типів + повна збірка у dist/
npm run preview      # переглянути зібраний сайт локально
npm run check:links   # перевірити, що всі внутрішні посилання в dist/ робочі
```

## Як редагувати контент

Увесь контент, який можна міняти без знання коду, лежить у `src/data/`:

| Файл | Що там |
|---|---|
| `src/data/site.ts` | Назва, телефон, Instagram, адреса, координати, графік роботи |
| `src/data/services.ts` | 7 категорій послуг і прайс (назва, тривалість, ціна) |
| `src/data/masters.ts` | Майстри: ім'я, спеціалізація, досвід, опис, фото |
| `src/data/reviews.ts` | Відгуки клієнток |
| `src/data/faq.ts` | Питання та відповіді |
| `src/data/gallery.ts` | Фото робіт у галереї (з прив'язкою до категорії послуги) |

Після зміни будь-якого файлу — просто зроби commit і push у гілку `main`
(або гілку, з якої відкрито Pull Request у `main`) — сайт перезбереться і
оновиться на GitHub Pages автоматично протягом 1–2 хвилин.

### ⚠️ Обов'язково перед публікацією наживо

1. **Телефон, адреса, графік роботи** в `src/data/site.ts` — зараз там приклад
   (`+38 (067) 123-45-67`, `вул. Хрещатик, 1`). Заміни на реальні дані.
2. **Координати салону** (`site.geo.lat` / `site.geo.lng`) — потрібні для карти
   на сторінці «Контакти». Знайти можна в Google Maps: правий клік по точці на
   карті → перше число у спливному меню це широта (lat), друге — довгота (lng).
3. **Instagram** — коли з'явиться посилання на профіль, встав його в
   `site.instagram` (`src/data/site.ts`). Кнопка «Записатися» одразу почне
   вести туди замість дзвінка, і на сайті з'являться коректні підписи на
   кнопках («Написати в Instagram» замість «Зателефонувати»).
4. **Ціни в `src/data/services.ts`** — зараз орієнтовні. Онови на реальний прайс.
5. **Відгуки в `src/data/reviews.ts`** — зараз це приклади з позначкою
   «Приклад відгуку», а не справжні відгуки клієнток. **Обов'язково заміни їх
   на реальні відгуки** (або перенеси кілька з Google-профілю салону) —
   публікувати вигадані відгуки під виглядом справжніх не варто.
6. **Фото** — зараз усюди використані власноруч згенеровані декоративні
   SVG-заглушки у фірмових кольорах (не фотографії, і не видають себе за
   такі). Як з'являться реальні фото робіт, інтер'єру та майстрів:
   - додай файли в `public/images/gallery/`, `public/images/masters/`,
     `public/images/services/` (можна перезаписати наявні `.svg`-файли
     фотографіями `.jpg`/`.webp` — просто онови розширення в шляху в
     `src/data/*.ts`);
   - для найкращої якості на весь екран досить ширини ~1200px для фото послуг
     і ~800×800 для фото майстрів.

## Дизайн

Кольори, шрифти, відступи — все через CSS-змінні в `src/styles/tokens.css`.
Щоб змінити фірмову палітру чи шрифти — досить відредагувати цей один файл.

Шрифти (Cormorant Garamond для заголовків, Manrope для тексту) зберігаються
локально в `src/fonts/` — сайт не робить зовнішніх запитів до Google Fonts.

## Безпека

- Сайт повністю статичний: немає бекенду, бази даних, форм чи збереження
  особистих даних відвідувачів.
- Суворий Content-Security-Policy (`src/layouts/BaseLayout.astro`): жодних
  inline-скриптів, лише файли з самого сайту.
- Карта Google Maps на сторінці «Контакти» підвантажується лише після
  натискання кнопки користувачем — жодних запитів до Google до цього моменту.
- `npm audit` перевіряється автоматично в CI при кожному Pull Request.

## Деплой на GitHub Pages

Публікація автоматична через `.github/workflows/deploy.yml` при push у `main`.
**Одноразово потрібно ввімкнути GitHub Pages вручну:**

1. Репозиторій має бути **публічним** (для приватних репозиторіїв GitHub Pages
   потребує платного плану).
2. У репозиторії: **Settings → Pages → Build and deployment → Source** →
   вибрати **GitHub Actions** (не «Deploy from a branch»).
3. Settings → Pages → **Enforce HTTPS** — увімкнено за замовчуванням, просто
   перевір, що галочка стоїть.
4. Після першого успішного деплою сайт буде доступний за адресою:
   `https://domanskyi-mykola.github.io/Lady_Victoria/`

### Перехід на власний домен (наприклад, ladyvictoria.com.ua)

1. У Settings → Pages → Custom domain — вкажи домен, додай файл `CNAME` (Astro
   зробить це автоматично, якщо прописати домен у Pages).
2. У `astro.config.mjs` зміни `site` на новий домен і `base` на `'/'`.
3. У `public/robots.txt` онови посилання на sitemap.
4. У `src/lib/routes.ts` та `src/lib/paths.ts` нічого міняти не треба — вони
   самі підхоплять новий `base`.

## SEO-чекліст після публікації

Сайт вже налаштований технічно (унікальні title/description на кожній
сторінці, sitemap.xml, structured data для Google — `BeautySalon`, `Service`,
`FAQPage`), але без цих кроків Google може не показати сайт одразу:

1. **Google Search Console** (search.google.com/search-console) — додай сайт,
   підтверди права власності, надішли `sitemap-index.xml`
   (`https://domanskyi-mykola.github.io/Lady_Victoria/sitemap-index.xml`).
2. **Google Business Profile** (business.google.com) — для салону краси це
   часто важливіше за сайт: саме звідси клієнти знаходять вас у Google Картах
   і локальній видачі. Вкажи там телефон, адресу, графік і посилання на сайт.
3. Після заповнення реальних відгуків клієнток — попроси кількох клієнток
   залишити відгук і в Google Business Profile теж.
4. За можливості — власний домен (див. вище) замість `github.io`: це
   підвищує довіру відвідувачів і трохи допомагає ранжуванню.

## Структура проєкту

```
src/
├── data/       контент сайту (телефон, ціни, майстри, відгуки, FAQ, галерея)
├── fonts/       шрифти (Cormorant Garamond, Manrope) — локальні .woff2
├── layouts/      BaseLayout.astro — SEO-теги, CSP, structured data, шапка/підвал
├── components/    перевикористовувані блоки (кнопки, картки, галерея, карта…)
├── lib/        допоміжні функції (шляхи з урахуванням base, JSON-LD)
├── styles/      CSS-змінні (tokens.css) і глобальні стилі
└── pages/      сторінки сайту (маршрутизація за файлами)

public/
├── scripts/     клієнтський JS (мобільне меню, лайтбокс, карта…)
├── images/      фото/заглушки послуг, майстрів, галереї
└── robots.txt, favicon.svg, apple-touch-icon.png, og-image.jpg

tools/
└── check-links.mjs  перевірка внутрішніх посилань у зібраному dist/ (CI)
```

Клієнтський JS навмисно лежить у `public/scripts/` як звичайні зовнішні
файли (а не всередині `src/`, звідки Astro міг би зібрати їх в один inline
`<script>`) — це потрібно, щоб суворий CSP (`script-src 'self'`, без
`'unsafe-inline'`) нічого не заблокував. Так само шрифти лежать у `src/fonts/`,
а не в `public/fonts/`, — так Vite сам коректно підставляє шлях з урахуванням
`base` (`/Lady_Victoria/...`) при збірці.
